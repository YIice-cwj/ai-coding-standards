## 1. 规范规则对照表

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-STYLE-INDENT]** | MUST | 依语言官方标准（PEP 8/gofmt/Google Style）；统一 UTF-8 (无 BOM) + LF (`\n`) | 混用 Tab 与空格；使用 CRLF 换行 |
| **[R-CMT-PURE]** | MUST | 业务逻辑与算法集中写于函数上方文档注释（`/** */` 或 `"""`）；零行内业务注释 | 函数体内写业务解释；注释写独白或残留死代码 |
| **[R-CMT-ALLOW]** | EXCEPTION | 仅放行静态分析指令（`// NOLINT`, `# type: ignore`, `// eslint-disable`） | 滥用静态分析指令掩盖真实错误 |
| **[R-NAME-SEM]** | MUST | 标识符具直观业务含义；常量全大写下划线（`MAX_LIMIT`）；已有项目保持既有风格 | 单字母命名（循环索引除外）；隐晦无意义缩写 |
| **[R-NAME-PRIV]** | MUST | 弱访问控制语言（Python）私有成员统一单下划线 `_` 前缀 | 使用双下划线 `__`（破坏继承多态，且属系统保留字） |

## 2. 注释纯粹性微对比 (❌ vs ✅)

```cpp
// ❌ 反例：函数内写业务行内注释（严重违背 B-CMT）
int calc_score(const user_data_t& user) {
    const int bonus = user.active_days * BONUS_PER_DAY; // 活跃天数加成（错！）
    return user.base_score + bonus - user.violations * PENALTY; // 业务扣分（错！）
}

// ✅ 正例：思路前置于文档头，函数内零业务注释，自解释清晰
/** 计算用户综合得分：基础分 + 活跃度加成 - 违规惩罚。 */
int calc_score(const user_data_t& user) {
    const int bonus = user.active_days * BONUS_PER_DAY;
    return user.base_score + bonus - user.violations * PENALTY;
}
```

## 3. 自检清单 (Checklist)
- [ ] 源码为 UTF-8 无 BOM 与 LF 换行，缩进符合既有约定。
- [ ] 函数体内零业务解释性行内注释，关键思路集中于头部文档。
- [ ] 标识符语义自解释，无无意义缩写，常量大写命名。
