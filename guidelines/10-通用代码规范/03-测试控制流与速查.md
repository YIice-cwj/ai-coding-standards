## 7. 测试规范

- **单测覆盖与可复现性**：新功能与核心逻辑重构**必须**配套单元测试，测试用例必须覆盖正常路径、边界值与错误路径。
- **严禁在测试中 sleep 盲等**：测试异步逻辑时，**禁止使用硬编码的 `sleep(3000)`**，必须使用事件回调、轮询检查（带超时上限）或虚拟时钟（Mock Timers）。

## 8. 控制流与代码简洁原则

### 8.1 提前返回 (Guard Clause)
- 函数主逻辑**必须**保持线性一路向下，禁止深层嵌套：

**正例**：
```python
def process_order(order: Order) -> bool:
    if not order.is_valid:
        return False
    if order.is_cancelled:
        return False
    return execute_payment(order)
```

**反例**：
```python
def process_order(order: Order) -> bool:
    if order.is_valid:
        if not order.is_cancelled:  # 嵌套右移
            return execute_payment(order)
    return False
```

### 8.2 必要防御原则与杜绝过度防御（多语言对照）

> **准则定义（SSOT）**：[行为规范 · Stage 3](../00-行为规范/01-核心铁律与五阶执行模型.md#stage-3-极简实现与最小变更)（"非必死不判断"、外部不可信边界必须校验 vs 内部受信任链路契约信任）。本节仅保留多语言**专有正反例**，不再复述准则条文。

**正例 (Python - 像人类工程师一样聚焦关键业务边界)**：
```python
def process_user_payment(order: Order, wallet: Wallet) -> bool:
    """处理用户支付扣款。仅校验余额不足这一真实业务边界。"""
    if wallet.balance < order.total_amount:
        return False
    wallet.deduct(order.total_amount)
    return True
```

**反例 (Python - AI 典型的神经过敏过度防御)**：
```python
def process_user_payment(order: Order, wallet: Wallet) -> bool:
    if order is None: return False              # 错！内部上游已保证非空
    if wallet is None: return False             # 错！类型标注与上游已保证非空
    if order.total_amount is None: return False  # 错！模型字段不变量已保证
    if order.total_amount < 0: return False      # 错！订单创建时已校验金额合法
    if wallet.user_id != order.user_id:          # 错！已由权限中间件校验，此处纯属臆想防御
        return False

    if wallet.balance < order.total_amount:
        return False
    wallet.deduct(order.total_amount)
    return True
```

### 8.3 安全等价合并与死代码消除 (Dead Code & Equivalent Simplification)

> **准则定义（SSOT）**：[行为规范 · Stage 3](../00-行为规范/01-核心铁律与五阶执行模型.md#stage-3-极简实现与最小变更) 安全优化放行特权。
> **放行原则**：在触及的代码范围内，发现明确**未引用的无用变量、死代码、或能用更少代码实现且可读性更高的等价合并**时，在确认 100% 行为等价与零破坏性的前提下，**允许直接修改优化，无需事先征求同意**。
> **底线**：严禁未经充分求证的盲目简化破坏隐式业务契约。

## 附录 B：通用代码审查高频陷阱

| 检查项 | 违规表现 | 正确做法 |
|---|---|---|
| **注释滥用** | 在函数内部随处打 `// 赋值给 x` 或写无关废话 | 删掉内部行内注释，将纯粹业务思路写在函数头部文档中 |
| **类型逃逸** | TypeScript 遇到复杂对象直接标 `any` | 定义清晰的 `interface` 或使用 `unknown` + 类型保护 |
| **错误吞没** | `catch (e) {}` 里面什么都不做 | 捕获具体类型，记录包含上下文的日志并处理/重新抛出 |
| **异步悬挂** | 直接调用异步函数而不 `await` | 必须显式 `await` 或接入结构化 Promise 错误链条 |
| **依赖失控** | `package.json` 写入 `"lodash": "*"` | 使用明确兼容版本并提交 `lockfile` |
| **安全红线** | 代码里写死了 `apiKey = "sk-..."` | 迁移到环境变量或秘密管理器中动态注入 |
| **控制流** | 4 层 `if-else` 嵌套包着核心业务 | 使用 Guard Clause 提前返回，拉平主干逻辑 |
| **过度防御** | 每一个调用子函数都再判一次入参是否为 null，为 0.1% 极小概率设卡 | 坚持必要防御原则，非确定不判断就会出错绝不添加判断，内部遵循契约 |
