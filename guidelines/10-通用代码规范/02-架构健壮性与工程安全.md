## 1. 架构设计：工程七大守则与平滑演进

| 原则标识 | 核心要求 | 违规反模式 (DON'T) |
|:---:|---|---|
| **SRP** | 单一职责：模块与函数单一聚焦 | 几百行包含多种职责的巨型函数 |
| **OCP** | 开闭原则：对扩展开放，对修改关闭 | 每次增需求都深度修改已有核心分支 |
| **LSP** | 里氏替换：派生类必须完全兼容基类行为 | 子类重写破坏父类前置/后置条件 |
| **DIP** | 依赖倒置：依赖抽象接口而非具体底层实现 | 高层业务直接强耦合具体底层库 |
| **ISP** | 接口隔离：精简接口，按需依赖 | 强迫调用方依赖不需要的庞杂方法 |
| **DRY** | 杜绝重复：逻辑集中收敛，拒绝 Copy-Paste | 复制粘贴相似逻辑，散落各处维护困难 |
| **KISS** | 极简至上：保持直接，坚守 YAGNI | 过度抽象、预留未来无用接口 (B4) |

### 单文件单类与职责边界 (R-ARCH-CLASS)

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-ARCH-CLASS]** | MUST | **一个文件只承载一个类**（声明与实现文件一一对应；仅有头文件的类型可只保留声明）；**例外**：纯类型定义聚合文件（如 `Types.h`）可集中声明多个无行为的基础类型、别名与枚举；**嵌套类**仅作为该类的内部实现细节（迭代器、Builder、私有数据契约）且归属清晰；**类只做职责内的事**：UI 类只负责展示与交互绑定，数据修改/持久化/业务规则交由服务层、命令层或用例层 | 一个 `.h/.cc` 堆叠多个业务类；嵌套与宿主无关的业务类或借嵌套规避单文件单类；在 `Types.h` 塞业务实现；UI 类直接修改业务数据或写库；网络层拼 UI；持久化层夹带业务规则；上帝类跨层越权 |

**职责边界示例**（UI 只展示与派发意图，数据变更经命令层）：

```cpp
// ❌ 反例：UI 类越权，直接修改数据并持久化
void inventory_panel_t::on_drop_item(const item_t& item) {
    inventory_.remove(item);              // 越权：UI 直接改业务数据
    save_to_disk(inventory_);             // 越权：UI 直接持久化
    refresh_slots();
}

// ✅ 正例：UI 仅派发用户意图；命令层负责校验、修改与持久化，事件回推后刷新展示
void inventory_panel_t::on_drop_item(const item_t& item) {
    drop_item_command_.execute(item);
}

void inventory_panel_t::on_inventory_changed(const inventory_t& inventory) {
    render_slots(inventory);
}
```

### 平滑演进规范 (Expand-Contract 模式)
公共 API 升级或架构迁移时，**严禁大爆炸式破坏性重写**：
1. **展开 (Expand)**：新增新契约，旧契约保持可用并通过桥接适配新实现，保证全库随时可编译；
2. **迁移 (Migrate)**：调用方逐个迁移至新契约，逐步验证；
3. **收缩 (Contract)**：旧接口标记废弃，流量清零后安全移除旧实现。

## 2. 健壮性与错误处理规范

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T) |
|---|:---:|---|---|
| **[R-ROBUST-TYPE]** | MUST | TS/Python/Go/Rust 显式标注公共类型；TS 严禁 `any` | 滥用 `any` 破坏类型系统；Python 省略形参返回标注 |
| **[R-ROBUST-ERR]** | MUST | 精确捕获具体异常类型；外部资源 100% 释放 (RAII/defer/using) | 空 `catch {}` 吞异常；捕获顶层 `Exception` 掩盖错误 |
| **[R-ROBUST-ASYNC]**| MUST | 异步调用必须显式处理（`await` / `.catch()` / 结构化取消） | 产生 Floating Promise 悬垂协程；未同步并发竞态 |
| **[R-ROBUST-CFG]**  | MUST | 遵循 12-Factor，敏感配置由环境变量注入；启动时校验并快速失败 | 硬编码配置；`.env` 提交至仓库；缺少类型强校验 |

```cpp
// ❌ 反例：丢失异步 Future 且吞异常
try {
    fetch_user_data(user_id);
} catch (...) {}

// ✅ 正例：显式等待并精确处理具体错误
try {
    const auto user = fetch_user_data(user_id).get();
} catch (const network_timeout_error& e) {
    return fallback_user_data;
}
```
