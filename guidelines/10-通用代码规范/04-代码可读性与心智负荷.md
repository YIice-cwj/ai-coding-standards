## 1. 核心约束与红线对照表

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-READ-VAR]** | MUST | 复合业务条件通过**具名意图常量 (Explaining Variables)** 解构 | 条件语句中堆砌长火车表达式；用行内注释解释条件 (违背 B-CMT) |
| **[R-READ-NEST]**| MUST | Guard Clause 线性平铺；控制流有效嵌套深度 $\le 3$ 层 | 深度嵌套超过 3 层；使用多层嵌套三元表达式（仅允许单层） |
| **[R-READ-MAGIC]**| MUST | 字面量必须提取为自解释常量（`SECONDS_PER_DAY`）或枚举 | 业务逻辑中散落魔数（`86400`）或神秘字符串（`"P"`） |
| **[R-NAME-POS]** | MUST | 布尔量强制正向命名（`is_ready`, `has_token`） | 反向或否定词命名（`is_not_valid`, `no_sync` 引发双重否定） |
| **[R-NAME-PAIR]**| MUST | 体系内动词严格成对（`get/set`, `add/remove`, `create/destroy`, `start/stop`） | 动词混配（如 `add_item()` 搭配 `delete_item()`） |
| **[R-NAME-UNIT]**| MUST | 物理量在后缀显式标注单位（`timeout_ms`, `max_bytes`, `angle_deg`） | 裸数值让调用方猜测单位（如 `timeout = 30`） |
| **[R-FUNC-SLAP]**| MUST | 单一抽象层次 (SLAP)：高层编排仅调业务函数，底层细节单独封装 | 高层业务编排中混入底层位运算、正则或报文拼装 |
| **[R-FUNC-FLAG]**| MUST | 消除裸布尔控制耦合：拆为具名函数或使用 Options 对象 | 传入裸布尔字面量控制分支（如 `render(data, true, false)`） |
| **[R-FUNC-CQS]** | MUST | 命令查询分离：查询只读幂等，命令改变状态 | 在 `get_`/`find_` 查询中隐蔽触发状态修改与写库 |
| **[R-MAINT-ERR]**| MUST | 异常具备**可排障三要素**：①发生什么；②实参上下文；③排查指引 | 抛出无实参上下文的单薄异常（`throw Error("fail")`） |
| **[R-MAINT-SEQ]**| MUST | 对象通过构造/工厂保证初始完备，消除隐式时序依赖 | 依赖隐式调用顺序（如必须先 `init()` 再 `config()` 否则崩溃） |

## 2. 模式对比与正反例 (❌ vs ✅)

### 2.1 意图变量解构长条件 [R-READ-VAR]
```cpp
// ❌ 反例：复合火车表达式 + 违规行内注释
if ((user.tier == vip || user.points > 1000) && cart.total() >= 200 && !promo.expired()) { ... }

// ✅ 正例：意图自解释常量，零行内注释，业务如自然语言
const bool is_privileged = user.tier == vip || user.points > 1000;
const bool meets_threshold = cart.total() >= MIN_PROMO_THRESHOLD;
const bool is_promo_valid = !promo.expired();
if (is_privileged && meets_threshold && is_promo_valid) { ... }
```

### 2.2 单一抽象层次原则 (SLAP) [R-FUNC-SLAP]
```cpp
// ❌ 反例：高层业务函数中撕裂式混入底层字节校验
void handle_event(std::string_view raw) {
    if (raw.find('|') == std::string_view::npos) throw std::invalid_argument("err");
    // 穿插 15 行原始校验与累加计算...
    notify_user(raw);
}

// ✅ 正例：抽象层次严格对齐，主流程一目了然
void handle_event(std::string_view raw) {
    const event_t event = parse_and_validate_payload(raw);
    notify_user(event);
}
```

### 2.3 可排障异常三要素 [R-MAINT-ERR]
```cpp
// ❌ 反例：无上下文无法排障
throw std::runtime_error("Invalid order status");

// ✅ 正例：具备“原因 + 现场参数 + 解决指引”
throw invalid_order_state_error(std::format(
    "Cannot cancel order id={}: status is '{}', expected 'PENDING'. For paid orders, initiate refund flow.",
    order_id, order.status_string()
));
```

## 3. 自检清单 (Checklist)
- [ ] 复合长条件解构成具名意图常量，嵌套深度 $\le 3$ 且无多层三元。
- [ ] 零散落魔数，物理量具单位后缀，布尔全部正向命名。
- [ ] 遵循 SLAP 原则，无裸布尔 Flag 参数控制，CQS 命令查询职责分明。
- [ ] 异常携带可排障三要素（原因 + 上下文参数 + 修复指引）。
