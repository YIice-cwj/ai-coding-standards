## 1. 核心可观测与隐私红线对照表

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-OBS-PII]**  | MUST | PII 强制掩码（手机 `138****1234`；身份证保前2后2；卡号保后4）；密码/PIN 绝对不输出 | 日志、监控或错误信息中明文打印用户隐私信息 |
| **[R-OBS-SEC]**  | MUST | 系统机密（API Key/Token/私钥/数据库密码）全量遮蔽为 `[REDACTED]` 或 `***` | 任何形式向终端、日志或返回体暴露明文凭据 |
| **[R-OBS-LOG]**  | MUST | 日志采用结构化键值（JSON/KV）；分级严格（`DEBUG` 生产默认关闭，`INFO` 记里程碑）；全链路贯穿 `trace_id` | 非结构化字符串拼接；业务错误无 `trace_id`；生产开启 DEBUG 刷屏 |
| **[R-OBS-HOT]**  | MUST | 吞吐量 $\ge 1000 \text{ ops/sec}$ 的核心热路径严禁写日志；采用原子计数器度量 (Metrics) | 在高频网络包解包或轮询紧凑循环内打日志（引发 I/O 阻塞与丢日志） |
| **[R-OBS-PROBE]**| MUST | 存活探针（Liveness）**仅检查自身死锁/崩溃**；下游持久层外部依赖校验仅交由就绪探针（Readiness） | 存活探针中检查数据库连接（数据库抖动导致容器级联重启雪崩） |
| **[R-OBS-METRIC]**| MUST | 对外服务端点必须暴露 **RED 指标**（Rate 吞吐量、Errors 错误率、Duration 耗时分位线 P95/P99） | 仅关注平均耗时；缺少请求率与错误率度量 |

## 2. 模式对比与正反例 (❌ vs ✅)

### 2.1 结构化日志与凭据脱敏 [R-OBS-PII / R-OBS-LOG]
```cpp
// ❌ 反例：非结构化、无 Trace、明文输出敏感信息
LOG_INFO("User " + username + " logged in with password " + password);

// ✅ 正例：结构化字段、绑定 Trace ID、敏感字段绝对脱敏
LOG_INFO("user_login_success",
    log_field("trace_id", ctx.trace_id()),
    log_field("user_id", user.id()),
    log_field("ip", ctx.client_ip())
);
```

### 2.2 类型安全机密包装器 [R-OBS-SEC]
```cpp
// ✅ 正例：类型系统强制脱敏输出，防止误打明文
class secret_string_t {
public:
    explicit secret_string_t(std::string val) : val_(std::move(val)) {}
    [[nodiscard]] std::string_view unmasked() const noexcept { return val_; }
    [[nodiscard]] std::string_view masked() const noexcept { return val_.empty() ? "" : "[REDACTED]"; }
private:
    std::string val_;
};
```

## 3. 自检清单 (Checklist)
- [ ] 日志输出无明文手机号、身份证、密码或 API Key。
- [ ] 日志格式结构化且绑定 `trace_id`，生产环境 `DEBUG` 已关闭。
- [ ] 高频热循环内零日志写盘，采用原子 Metrics 度量。
- [ ] 存活探针（Liveness）与就绪探针（Readiness）严格解耦，存活探针不检测外部依赖。
