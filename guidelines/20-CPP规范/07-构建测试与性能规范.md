## 1. Modern CMake 与依赖管理

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-CPP-BUILD-TARGET]** | MUST | 使用 Target-based CMake：`target_link_libraries`、`target_include_directories`、`target_compile_features` | 全局 `include_directories`/`link_libraries`；污染全局 `CMAKE_CXX_FLAGS`；把实现细节暴露为 PUBLIC |
| **[R-CPP-BUILD-WARN]** | MUST | 编译选项 `-Wall -Wextra -Wpedantic -Werror`；Debug/Test 构建启用 ASan/UBSan | 关闭警告或全局 `-Wno-*` 掩盖问题；Release 包携带 Sanitizer |
| **[R-CPP-BUILD-DEP]** | MUST | 依赖通过 vcpkg/Conan/FetchContent 等锁定版本；构建可复现；第三方代码不直接改源码 | 无版本约束的 `FetchContent`；把第三方源码复制进仓库后随意修改；依赖系统全局库 |
| **[R-CPP-BUILD-STATIC]** | MUST | CI 执行 clang-tidy/cppcheck 等静态分析；格式化使用 clang-format | 仅靠人工 Review 发现静态问题；提交未格式化的代码 |

```cmake
add_library(core STATIC src/core.cc)
target_include_directories(core PUBLIC include)
target_compile_features(core PUBLIC cxx_std_20)
target_compile_options(core PRIVATE -Wall -Wextra -Wpedantic -Werror)
target_link_libraries(core PRIVATE fmt::fmt)
```

## 2. 测试框架与覆盖率

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-CPP-TEST-FRAME]** | MUST | 使用 GoogleTest/Catch2；测试命名表达行为；Fixture 隔离；异步测试用事件/虚拟时钟同步 | 测试依赖执行顺序；共享可变 Fixture；`sleep_for` 盲等 |
| **[R-CPP-TEST-COV]** | MUST | 使用 gcov/lcov 或 llvm-cov 统计行/分支覆盖率；核心业务遵循 [10/03](../10-通用代码规范/03-测试控制流与速查.md) 的 95% 门禁 | 仅统计行覆盖不统计分支；用排除注释/白名单虚抬覆盖率 |
| **[R-CPP-TEST-SAN]** | MUST | CI 至少执行 ASan + UBSan；并发代码增加 TSan；Sanitizer 失败即阻断 | 只在本地手工跑 Sanitizer；忽略 Sanitizer 报告 |
| **[R-CPP-BENCH]** | MUST | 性能敏感代码使用 Google Benchmark 等可复现基准；Release 构建、预热、重复 $\ge 5$ 轮、报告中位数与离散度，并记录编译器/硬件/构建参数 | 无基线宣称优化；Debug 构建或覆盖率插桩下测；单次运行下结论；把基准计入覆盖率 |

```cpp
TEST(order_service_test, rejects_insufficient_balance) {
    order_service_t service;
    wallet_t wallet{.balance_cents = 3000};

    const auto result = service.process(order_t{.id = "ord_001", .amount_cents = 5000}, wallet);

    ASSERT_FALSE(result.has_value());
    EXPECT_EQ(result.error(), payment_error_t::insufficient_balance);
    EXPECT_EQ(wallet.balance_cents(), 3000);
}
```

### 2.1 基准测试落地

```cpp
void BM_order_lookup(benchmark::State& state) {
    order_repository_t repository = make_repository_with_orders(10000);
    for (auto _ : state) {
        const auto order = repository.find_by_id("ord_05000");
        benchmark::DoNotOptimize(order);
    }
}

BENCHMARK(BM_order_lookup)->Unit(benchmark::kNanosecond);
```

- **关键开关**：`--benchmark_repetitions=5 --benchmark_report_aggregates_only=true`、`--benchmark_min_time`、`--benchmark_out=bench.json --benchmark_out_format=json`；基线对比使用 Google Benchmark 官方 `tools/compare.py` 或等价脚本。
- **等价替代**：已使用 Catch2 的项目可用其 `BENCHMARK` 宏；禁止为同一模块并行维护第二个基准框架。
- **口径回链**：环境、统计量与门禁遵循 [10/03 §5](../10-通用代码规范/03-测试控制流与速查.md#5-性能验证与基准测试-performance-verification--benchmarking)。

## 3. 性能、ABI 与序列化

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-CPP-PERF-PROFILE]** | MUST | 先 profile（perf/VTune/Tracy）再优化；微基准以中位数与离散度验收，端到端/服务以 P95/P99 与吞吐量验收；保留基线数据 | 凭直觉优化；微基准套用 P95/P99；只测平均值；无复现命令的性能结论 |
| **[R-CPP-PERF-HOT]** | MUST | 热路径减少分配、锁、日志与虚调用；容器预留容量；优先连续内存与缓存局部性 | 热循环内 `new`/字符串拼接/日志；无界缓存；过早微优化 |
| **[R-CPP-ABI]** | MUST | 公共库使用导出宏/符号可见性控制；跨编译器边界避免 STL 类型进入 ABI；接口版本化 | 公共 ABI 暴露 `std::string`/`std::vector` 等实现细节；无版本约束的二进制接口 |
| **[R-CPP-SERIAL]** | MUST | 序列化格式带版本号；反序列化校验字段与范围；保持向后兼容；禁止反序列化裸指针 | 直接 `memcpy` 结构体落盘；无版本迁移；信任外部二进制数据 |

#  else
#    define CORE_API __declspec(dllimport)
#  endif
#else
#  define CORE_API __attribute__((visibility("default")))
#endif

## 4. 自检清单

- [ ] CMake 使用 target-based 写法，无全局编译/链接污染。
- [ ] 警告与 Sanitizer 在 CI 强制执行，Release 不携带 Sanitizer。
- [ ] 依赖锁定版本且构建可复现，第三方代码未被直接修改。
- [ ] 测试覆盖主通路、边界、异常与并发，无 sleep 盲等。
- [ ] 核心业务行/分支覆盖率 ≥95%，报告可复现。
- [ ] 性能结论有 profile/benchmark 基线，记录编译器、硬件与构建参数；微基准使用 Release 构建、重复轮次与中位数/离散度，不以 P95/P99 判定。
- [ ] 基准独立于功能测试套件，未计入覆盖率统计。
- [ ] 热路径无高频分配、锁竞争、日志与无界缓存。
- [ ] 公共 ABI 有导出/可见性控制与版本化；序列化格式具备版本与校验。
