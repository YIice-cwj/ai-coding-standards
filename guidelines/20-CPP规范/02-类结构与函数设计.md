## 4. 类结构规范（接口优先原则）

类声明内部**必须**严格遵循以下 15 层顺序组织，坚持“公开接口优先 (Interface-First)”：

```cpp
class example_t {
public:    // 1. public 类型定义 (using / enum class)
protected: // 2. protected 类型定义
private:   // 3. private 类型定义
public:    // 4. public 常量 (static constexpr)
protected: // 5. protected 常量
private:   // 6. private 常量
public:    // 7. public 成员函数 (构造/析构/核心业务接口 - 接口优先对外展现)
protected: // 8. protected 成员函数
private:   // 9. private 成员函数 (带 _ 后缀)
public:    // 10. public 静态函数
protected: // 11. protected 静态函数
private:   // 12. private 静态函数
private:   // 13. private 成员变量与静态变量 (带 _ 后缀，实现细节封装于底)
protected: // 14. protected 成员变量与静态变量
public:    // 15. public 成员变量与静态变量 (纯数据 POD/struct 除外，普通 class 极力避免)
};
```

- **实现顺序对齐**：源文件（`.cc` / `.cpp`）中的函数实现顺序，**必须与头文件类声明中的先后顺序 1:1 严格对齐**。

## 5. 头文件与依赖规范

- **文件职责**：`.h` 声明；`.cc` 实现；`.hpp` Header-only 库专用。
- **依赖控制**：统一使用 `#pragma once`；能使用前向声明（Forward Declaration）的指针/引用依赖必须使用前向声明。
- **内联放置**：头文件内小型内联函数集中放在对应访问控制区末尾；复杂函数类外定义。

## 6. 函数设计规范

### 6.1 基本设计约束
- **函数长度与参数**：建议行数 $\le 50$ 行；形参建议 $\le 4$ 个（过多封装为结构体）；**禁止非 const 引用输出参数**，通过返回值、结构体、`std::optional` 或 `std::expected` 返回。

### 6.2 控制流线性化与提前返回 (Guard Clause)
主逻辑保持线性一路向下，禁止深层嵌套：

```cpp
// ✅ 正例：Guard Clause
bool process_message(const packet_t& packet) {
    if (!packet.is_valid() || packet.payload().empty()) {
        return false;
    }
    return execute_dispatch(packet);
}

// ❌ 反例：多层嵌套右移
bool process_message(const packet_t& packet) {
    if (packet.is_valid()) {
        if (!packet.payload().empty()) {
            return execute_dispatch(packet);
        }
    }
    return false;
}
```

### 6.3 必要防御原则与严禁过度防御（Like Human Engineers）
> **准则 SSOT**：[行为规范 · Stage 3](../00-行为规范/01-核心铁律与五阶执行模型.md#stage-3-极简实现与最小变更)（非必死不判断，信契约弃臆想）。

- **充分信任 C++ 语言契约与内部不变式**：
  - **引用语义**：语法层面已保证绑定有效对象，**严禁判断 `&param == nullptr`**。
  - **this 指针**：成员函数内**严禁判断 `this == nullptr`**（标准 UB 且会被编译器优化掉）。
  - **类不变式**：内部私有函数调用时，**严禁重复检查**构造函数与状态机已维护的不变量。
  - **动态分配**：`make_unique` / `new` 失败默认抛 `bad_alloc`，**严禁在之后判断是否为 `nullptr`**。

```cpp
// ✅ 正例：像资深人类工程师一样直接清晰
bool inventory_t::add_item(const item_t& item) {
    if (items_.size() >= capacity_) { return false; }
    items_.push_back(item);
    return true;
}

// ❌ 反例：典型的神经过敏过度防御
bool inventory_t::add_item(const item_t& item) {
    if (this == nullptr || &item == nullptr) { return false; } // 错！语言契约保证绝不可能为空
    if (capacity_ <= 0 || item.id() <= 0) { return false; }   // 错！构造与上游已保证
    if (items_.size() >= capacity_) { return false; }
    items_.push_back(item);
    return true;
}
```

### 6.4 安全等价合并与死代码消除
在触及代码范围内，确证 100% 行为等价与零破坏性的未引用变量、死代码或高可读合并，**允许直接修改优化，无需征求同意**。
