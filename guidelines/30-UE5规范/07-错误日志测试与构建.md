## 14. 错误处理与断言

- **禁用异常**：UE5 默认开启 `-fno-exceptions`，**严禁使用 `throw` / `try-catch`**；必须使用错误码、`TOptional` 或 `TExpected`（UE5.3+）。
- **断言宏准则**：
  | 宏 | 用途与语义 | 发布构建行为 |
  |---|---|---|
  | `check(expr)` / `checkf` | 不变量检查（非必死不判断，仅限确定非法的不变式） | 自动移除 |
  | `ensure(expr)` / `ensureMsgf` | 软断言（记录调用栈警告，只报一次，不崩溃） | 依然保留 |
  | `verify(expr)` | 必须执行副作用表达式的不变量检查 | 表达式保留执行 |

## 15. 日志系统 (UE_LOG)

- 严禁裸 `printf` / `cout`；必须使用 `UE_LOG` 并用 `TEXT()` 包裹字面量。
- **日志级别**：`Fatal`（崩溃）、`Error`（严重错误）、`Warning`（警告）、`Log` / `Display`（普通）、`Verbose`（调试）。
- 高频循环（Tick / 帧逻辑）内严禁无限制打印日志。

```cpp
DEFINE_LOG_CATEGORY_STATIC(LogFlexiInventory, Log, All);
UE_LOG(LogFlexiInventory, Warning, TEXT("Slot %d is locked"), SlotIndex);
```

## 20. 自动化测试 (Automation Testing)

- **框架宏**：逻辑单测使用 `IMPLEMENT_SIMPLE_AUTOMATION_TEST`；异步测试使用 `IMPLEMENT_LATENT_AUTOMATION_TEST`。
- **禁 sleep 盲等**：严禁在测试中使用 `FPlatformProcess::Sleep` 盲等，必须使用 `TFuture` / `FEvent` 或 Latent 命令同步。

```cpp
IMPLEMENT_SIMPLE_AUTOMATION_TEST(FFlexiBagTest, "FlexiInventory.Bag.Add", EAutomationTestFlags::ApplicationContextMask | EAutomationTestFlags::ProductFilter)
bool FFlexiBagTest::RunTest(const FString& Parameters) {
    UFlexiBagComponent* Bag = NewObject<UFlexiBagComponent>();
    TestTrue(TEXT("Add item should succeed"), Bag->TryAddItem(TestItem, 5));
    return true;
}
```

## 21. 模块构建与设计模式 (Build.cs & Patterns)

- **Build.cs 规范**：显式指定 `CppStandard = CppStandardVersion.Cpp20;`；私有模块依赖必须放入 `PrivateDependencyModuleNames`（严禁滥放 Public 导致依赖污染）。
- **UE5 推荐设计模式**：
  - **单例**：必须使用 `USubsystem`（如 `UGameInstanceSubsystem`）替代手写单例。
  - **状态机**：优先使用 `FGameplayTag` 容器组合替代复杂枚举分支。
  - **解耦通信**：优先使用 UE5 委托（`DECLARE_DYNAMIC_MULTICAST_DELEGATE`）解耦模块。
