## 4. 类结构规范（接口优先原则）

> **继承 C++ 规范 4**。UE5 项目严格遵循“公开接口优先 (Interface-First)”与反射特性排布：

**必须**按以下顺序组织：

1. `public` 类型定义（含 USTRUCT 嵌套、using 别名）
2. `protected` 类型定义
3. `private` 类型定义
4. `public` 常量
5. `protected` 常量
6. `private` 常量
7. `public` 成员函数（含构造/析构/业务接口/UFUNCTION - 接口优先对外展现）
8. `protected` 成员函数
9. `private` 成员函数
10. `public` 静态函数
11. `protected` 静态函数
12. `private` 静态函数
13. `private` 成员变量（含 UPROPERTY）与静态变量
14. `protected` 成员变量与静态变量
15. `public` 成员变量（谨慎使用）与静态变量
16. UE5 反射与虚函数重写（如 `GetLifetimeReplicatedProps`，紧随对应访问控制区域）

**函数实现顺序必须与类中声明顺序一致**：`.cpp` 中的函数实现**必须**按照头文件中声明的先后顺序排列。

**内联函数放置**：UE5 项目全面取消 `.inl` 文件分离。普通极短内联实现（1~3 行 Getter/转发）允许放在头文件类声明内；复杂函数**严禁**在类内内联，**必须**放置在类声明体外（同在 `.h` 文件中）。

## 5. 头文件规范

### 5.1 文件后缀

| 文件类型 | 后缀 | 用途 |
|----------|------|------|
| 头文件 | `.h` | 类与接口声明（以及模板的完整声明与类外实现） |
| 源文件 | `.cpp` | 业务与函数实现（UE5 推荐 `.cpp`，旧代码可能用 `.cc`） |
| 头源合一 | `.hpp` | 声明+实现（UE5 项目**禁止**使用） |

### 5.2 UE5 头文件特殊要求

- **必须**使用 `#pragma once`
- **必须**在头文件最后 `#include "XXX.generated.h"`（UHT 强制）
- **必须**使用前向声明减少依赖
- **严禁**在头文件中 `using namespace`（见第 9 条）

```cpp
#pragma once

#include "CoreMinimal.h"
#include "Components/ActorComponent.h"
#include "FlexiBagComponent.generated.h"   // 必须最后

class UFlexiItemDataAsset;   // 前向声明
class UFlexiItemObject;
```

## 6. 接口设计规范

UE5 接口**必须**使用 `UINTERFACE` + `I` 前缀类双结构：

```cpp
// .h
UINTERFACE(MinimalAPI, Blueprintable)
class UFlexiBagFeatureInterface : public UInterface {
    GENERATED_BODY()
};

/**
 * @brief UI 功能子模块通信接口
 */
class FLEXIINVENTORY_API IFlexiBagFeatureInterface {
    GENERATED_BODY()

public:
    virtual ~IFlexiBagFeatureInterface() = default;  // 虚析构

    UFUNCTION(BlueprintNativeEvent, BlueprintCallable)
    void InitializeFeature(UFlexiBagMainWidget* MainBagWidget);
};
```

规则：
- `U` 前缀类**必须**继承 `UInterface`，**只**包含 `GENERATED_BODY()`
- `I` 前缀类**必须**包含虚析构函数与所有接口方法
- 实现：`class UMyClass : public UObject, public IFlexiBagFeatureInterface`
- C++ 侧用 `Cast<IFlexiBagFeatureInterface>(obj)` 判断是否实现
