## 二、 交付前强制预检体系 (Pre-Flight Protocol)

### 2.1 思考链（CoT）内省协议
大模型在输出最终答复或生成代码前，**必须在内部思考流中显式完成 3 项自问自答**：
1. **[计划对齐]**：本任务属于 L3/L4 吗？若是，是否已向用户提交计划文档并已获明确批准？
2. **[变更边界]**：检查 `git diff`，每一行代码是否严格属于当前任务或确证无害的死代码清理？是否存在越权排版？
3. **[必要防御]**：主干逻辑是否足够直接？是否存在针对内部可信链路或 0.1% 极小概率的多余防御设卡？

### 2.2 交付前逐项核验 Checklist
- [ ] **1. 澄清与授权 (B1/B2)**：无猜想决策；L3/L4 计划文档已获批准；重构采用平滑演进。
- [ ] **2. 最小变更控制 (B3)**：`git diff` 严格局限在任务范围与确证死代码内，无无关变动。
- [ ] **3. 极简与 YAGNI (B4)**：零冗余抽象，无未来预留接口。
- [ ] **4. 必要防御与注释 100% 同步 (B4/B-CMT)**：内部链路信任契约；函数体内零业务注释；凡被修改或修复的函数，文档头注释已同步更新，且与最新代码实现 100% 保持一致。
- [ ] **5. 语言专有遵从**：严格依从 C++（15 层排布/RAII/防阻断 NRVO）或 UE5（UPROPERTY/命名法）等专有规范。
- [ ] **6. 客观多维验证 (B5)**：提供客观测试结果；无 sleep 盲等；无同义反复 Mock；精确断言业务值。
- [ ] **7. 缺陷源头根治 (B7)**：已定位破损不变式源头；已评估上下游影响；已全景排查全库同类模式。
- [ ] **8. 三振熔断兜底 (B8)**：未陷入盲目试错死循环（遇 3 次同类失败立即挂起求助）。
- [ ] **9. 工具与环境安全 (B-SEC)**：无高危命令；无私装依赖；无明文 Key；临时探针脚本已清理。
- [ ] **10. 记忆归档维护 (B6)**：临近上下文极限时已在 `.memory/` 归档并同步索引。
- [ ] **11. 文档与版本同步 (SemVer)**：API/架构变更已同步文档；规范变更已升级版本号与 INDEX.md。
- [ ] **12. 提交权限受控 (B-GIT)**：未获明确提交指令前，绝对不执行 `git commit` 或 `git push`。
