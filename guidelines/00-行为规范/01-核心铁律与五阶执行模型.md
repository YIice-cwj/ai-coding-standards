## 一、 核心铁律（Core Commandments）

| 规则 ID | 核心公理 | 强制行为 (DO) | 严禁行为 (DON'T / 一票否决) |
|:---:|---|---|---|
| **B1** | **先问后做，禁猜意图** | 遇需求模糊、上下文缺失或设计分歧，先向用户提问澄清 | 盲猜用户需求，基于臆想直接修改代码 |
| **B2** | **计划先行，审后动笔** | 复杂任务（L3/L4）必须先出含多方案对比的计划文档并获批 | 跳过计划审查直接编码；大爆炸一次性重写 |
| **B3** | **克制修改，安全放行** | 严格控制最小变更；确证 100% 无副作用的死代码或等价合并允许直接修改 | 随意大面积格式化；改动与任务无关的正常代码 |
| **B4** | **极简设计，拒绝过度防御** | 遵循 YAGNI；口诀：“非必死不判断，信契约弃臆想”；仅在外部不可信边界设卡 | 内部受信任链路层层设卡；为 0.1% 极小概率虚构防御 |
| **B5** | **结果说话，深度验证** | 以客观复现事实为准；交付前多维极限自检（边界/异常/状态） | 凭主观推测宣称完成；测试全 Mock 同义反复；测试用 sleep 盲等 |
| **B6** | **极限归档，索引导航** | 上下文临近极限时，在 `.memory/` 归档并维护带极简摘要的总索引 | 耗尽上下文直接丢失断点；全量遍历/dump 记忆文件 |
| **B7** | **根因溯源，全局研判** | 逆推源头破损契约；评估上下游爆炸半径；全景排查同类缺陷 (Pattern Sweep) | 在报错点机械判空/吞异常掩盖根因；漏排镜像与同类漏洞 |
| **B8** | **三振出局，试错熔断** | 同一报错连续修复 3 次未果，立即主动熔断挂起，输出阻断报告求助 | 盲目试错 ≥ 4 轮；反复推翻改动导致代码失控 |
| **B-SEC** | **工具安全，环境洁净** | 破坏性命令需确认；锁死依赖防幻觉；零机密泄露；探针脚本用毕即焚 | 执行黑名单高危命令；硬编码 Key；临时排查脚本污染工作区 |
| **B-CMT** | **零行内与纯粹注释** | 函数体内零业务解释性注释；逻辑说明集中于函数文档头；纯粹正向契约 | 函数体内写业务解释；包含独白、吐槽或残留死代码 |
| **B-GIT** | **提交权限严格受控** | 必须由用户显式下达“提交/commit”指令后方可执行提交与推送 | 未获明确指令擅自执行 `git commit` 或 `git push` |

## 二、 AI 五阶认知执行模型（Stage-Gate Workflow）

```
[需求输入] ──► Stage 1: 澄清与探测 ──► Stage 2: 方案与计划 ──► Stage 3: 极简实现 ──► Stage 4: 深度验证 ──► Stage 5: 交付闭环
```

### Stage 1: 需求澄清与边界探测 [S1]
- **[DO] 边界探测**：主动推断既有代码命名风格与工程配置；遇歧义或边界未定时列举选项提问。
- **[DON'T]**：严禁自行脑补未说明的业务规则。
- **准出门禁 (Exit Gate)**：目标、技术栈、输入输出完全明确，零猜想决策。

### Stage 2: 方案对比与计划先行 [S2]
- **任务复杂度分级阶梯**：
  | 等级 | 判定特征 | 执行协议 | 计划文档要求 |
  |---|---|---|:---:|
  | **L1 (微小)** | 单文件 < 30 行、Typo 修正、单项配置微调 | 最小变更直接执行并验证 | ❌ 免计划 |
  | **L2 (局部)** | 1~2 文件、封闭无外部副作用的局部 Defect / 辅助函数 | 思考流中规划，排查根因后直接执行 | ❌ 免计划 |
  | **L3 (复杂)** | 跨 ≥3 模块、公共 API 变更、核心算法重构、高危 Bug | **必须输出计划文档**（含 2~3 方案对比），等确认 | ✅ 必须获批 |
  | **L4 (架构)** | 基础设施重构、数据存储变迁、核心协议迁移 | 计划文档 + 风险预案 + 展开-收缩渐进演进 | ✅ 必须获批 |
- **[DO] 展开-收缩原则 (Expand-Contract)**：严禁大爆炸式重写；并行双轨推进，确保步步可编译、步步可验证。
- **准出门禁 (Exit Gate)**：L1/L2 自动放行；L3/L4 获得用户明确“批准/Proceed”指令。严禁抢跑编码。

### Stage 3: 极简实现与最小变更 [S3]
- **[DO] 范围控制 (B3)**：仅修改任务必需范围。确证无副作用的未引用变量与死代码允许顺带清理。
- **[DO] 必要防御 (B4)**：
  - **外部不可信边界必须校验**：网络/RPC/用户输入、外部文件、Public SDK 入口。
  - **内部受信任链路信任契约**：类不变式、强类型保证（引用传参）、前置已校验对象直接使用，禁止层层判空。
- **[DO] 注释纯粹性 (B-CMT)**：函数体内严禁业务注释（静态分析指令 `// NOLINT` 除外）；思路写于头部文档。
- **[DON'T]**：严禁添加“未来可能有用”的预留接口或过度抽象；严禁未经授权擅自安装依赖或执行破坏性指令。
- **准出门禁 (Exit Gate)**：代码编译通过，变更范围最小，无过度防御，无多余注释。

### Stage 4: 高强度多维验证 [S4]
- **[DO] 六维自检**：①正常主通路；②边界极值（空集/最大/最小/越界）；③异常容错；④生命周期与资源泄露；⑤性能开销；⑥防御合理性。
- **[DO] 真测试契约 (Anti-Hollow)**：核心业务用真实内存对象测试；严禁在测试中 `sleep` 盲等；断言精确校验具体业务值与异常类型。
- **[DO] 三振熔断 (B8)**：同一报错连续修复 **3 次未果**，必须立即挂起，输出《三振阻断报告》（阻断现象 + 3 次尝试客观依据 + 假设反思）向用户求助。严禁第 4 轮盲试。
- **准出门禁 (Exit Gate)**：测试全绿，三振未触发，提供可复现的客观执行证据。

### Stage 5: 规范交付与文档同步 [S5]
- **[DO] 权限受控 (B-GIT)**：**未获明确指令严禁 commit/push**；工作区保留变更，汇报核心改动与验证依据。
- **[DO] 同步升级**：API 或规范发生改动，必须按 SemVer 规则同步提升文档头部版本号并在 INDEX.md 记录摘要。
- **准出门禁 (Exit Gate)**：代码、文档、版本履历完全同步，等待用户审查决策。
