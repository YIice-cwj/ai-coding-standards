## 二、 命令行与工具调用安全红线 (CLI Boundaries)

AI 在调用命令行与系统工具时，必须严格遵守以下红线：

### 1. 绝对禁止的破坏性黑名单（未经当面指令授权一律禁止）
- **文件系统粉碎**：`rm -rf /`, `rm -rf *`, `rm -rf ~`, `mkfs`, `fdisk`，或向系统级目录写入。
- **Git 历史破坏**：`git reset --hard`、`git clean -f -d`、`git push --force`（即使获得常规提交指令也严禁强推）。
- **数据不可逆清除**：`DROP DATABASE`、`DROP TABLE`、`TRUNCATE`、批量删除无 `WHERE` 条件的 SQL。
- **提权与系统修改**：`sudo` 提权、修改 `/etc/hosts`、修改防火墙或关闭安全审计。

### 2. 破坏性操作确认协议
- 清理构建产物（如 `rm -rf build/` 或 `cargo clean`）必须向用户明确汇报清理路径，获得明确许可后方可执行。

## 三、 依赖管理与防幻觉契约 (No Package Hallucination)

- **严禁擅自安装新依赖**：未经用户明确授权，禁止执行 `npm install <pkg>`、`pip install <pkg>`、`cargo add <pkg>`、`go get <pkg>`。必须先向用户汇报引入必要性、包体积与许可证合规性。
- **杜绝依赖幻觉验证**：在建议任何三方库前，必须在本地或官方索引确认该包真实存在且处于维护状态，严禁凭臆想生成虚构包名。
- **Lockfile 强制约束**：安装依赖必须严格同步更新 Lockfile（`package-lock.json`、`Cargo.lock`、`poetry.lock` 等），严禁浮动版本破坏可复现构建。

---

## 四、 机密信息零泄露契约 (Zero Secret Exposure)

- **禁止硬编码凭据**：源码、配置文件、单测、注释中严禁写入真实 API Key、Access Token、私钥或密码；示例一律使用假名（如 `sk-test-dummy`）。
- **禁止终端明文 Dump 凭据**：打印环境变量（`env`）或读取 `.env` 时，必须主动做脱敏处理，严禁将包含真实机密的日志暴露在控制台或对话中。
- **Git 提交防泄漏检查**：核验 `.gitignore` 确保已严格排除 `.env`、`*.key`、`*.pem`、`credentials.json` 等配置文件。

---

## 五、 工作区洁净度契约 (Workspace Hygiene)

- **临时探针脚本用毕即焚**：排查 Bug 或探测临时数据编写的一锤子脚本（如 `debug.py`、`probe.cc`），原则上置于临时沙箱目录（如 `.tmp/`）；**任务准出时必须自发彻底清理，严禁遗留源码目录**。
- **零脏编译产物残留**：单次测试或本地编译生成的可执行测试文件、临时日志与 dump 文件，验证完毕后及时回收，确保 `git status` 仅保留预期的业务与规范改动。

## 六、 审查核查项 (B-SEC Checklist)

- [ ] 是否杜绝了破坏性黑名单命令？清理操作是否获得确认？
- [ ] 是否杜绝了未经允许的第三方包新增与依赖幻觉？
- [ ] 是否杜绝了代码、日志或配置中的任何明文机密（Secret/Key）？
- [ ] 是否已彻底清理排查过程中创建的所有临时探针脚本与测试垃圾文件？
