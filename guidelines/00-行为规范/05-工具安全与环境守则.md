## 二、 命令行与系统工具安全红线

### 1. 绝对禁止的破坏性黑名单（无显式许可一律禁止）
- **文件破坏**：`rm -rf /`、`rm -rf *`、`rm -rf ~`、`mkfs`、写入系统目录（`/usr`, `/etc`）。
- **Git 历史破坏**：`git reset --hard`、`git clean -f -d`、`git push --force`（即使获得常规提交指令也严禁强推）。
- **数据不可逆清除**：`DROP DATABASE`、`DROP TABLE`、`TRUNCATE`、无 `WHERE` 条件的批量删除/更新。
- **系统篡改**：`sudo` 提权、修改 `/etc/hosts`、关闭防火墙或安全审计。

### 2. 破坏性清理确认协议
清理构建产物（如 `rm -rf build/`、`cargo clean`）必须向用户明确说明路径，获批后方可执行。

## 三、 依赖管理与防幻觉契约 (No Package Hallucination)
- **[FORBIDDEN] 严禁私装依赖**：未经用户明确许可，禁止执行 `npm i`、`pip install`、`cargo add`、`go get`。
- **[MUST] 真实性验证**：建议依赖前必须在本地或官方索引确认该包真实存在且处于活跃维护，严禁幻觉包名。
- **[MUST] Lockfile 锁版本**：安装依赖必须严格同步更新 lockfile，严禁使用 `latest` 等浮动版本。

---

## 四、 机密信息零泄露契约 (Zero Secret Exposure)
- **[FORBIDDEN] 严禁硬编码机密**：代码、注释、配置、单测中绝不出现真实 API Key、Token、私钥或密码。
- **[FORBIDDEN] 严禁终端 Dump 凭据**：打印环境变量或读取 `.env` 时必须做脱敏掩码（如 `sk-***`）。
- **[MUST] 仓库防泄漏**：核验 `.gitignore` 确保严格排除了 `.env`、`*.pem`、`*.key`、`credentials.json`。

---

## 五、 工作区洁净度契约 (Workspace Hygiene)
- **临时探针脚本用毕即焚**：为排查临时创建的辅助脚本（如 `probe.py`、`test.cc`），任务交付前必须彻底清理。
- **编译中间体零残留**：单次运行产生的可执行二进制、临时 dump 与临时日志及时回收，保持 `git status` 洁净。

---

## 六、 交付核查清单 (B-SEC Checklist)
- [ ] 零黑名单破坏性命令；清理操作已获明确许可。
- [ ] 零私自引入的三方依赖；无幻觉包名；Lockfile 保持同步。
- [ ] 零硬编码机密与终端明文凭据泄露。
- [ ] 零临时探针脚本遗留；编译生成垃圾文件已彻底清理。
