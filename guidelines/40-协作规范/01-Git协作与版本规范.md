# Git 协作与版本规范 (Git Collaboration & Versioning Standards)

**所属域**: 40-协作规范  **域版本**: 2.1.0  **日期**: 2026-10-21  **类型**: 全局通用协作规范（规则 SSOT）

> **SSOT 声明**：**"未获用户明确指令，严禁擅自提交" (B-GIT)** 铁律唯一完整定义于本文件 §1，全体系一律引用本处。
> **关联文档**：[核心铁律](../00-行为规范/01-核心铁律与五阶执行模型.md) · [规范体系总索引](../INDEX.md)

## 1. 提交权限与执行铁律 (B-GIT SSOT)

- **严禁擅自提交（Explicit User Trigger Only）**：
  - Git 提交是项目历史的正式固化动作，**必须经由用户显式指令（如明确说“提交”或“commit”）方可执行**。
  - 用户未明确要求提交前，**严禁自行执行 `git commit` 或 `git push`**。
  - 未获提交指令时，AI 只能在工作区保留修改并向用户汇报改动摘要，等待用户审查确认后由用户决定何时提交。

---

## 2. 提交信息格式契约

Git 提交信息必须采用结构化格式：

```
[类型]: 简短概述本次变更的核心目的（<= 50 字）
- 具体改动点1（说明改了什么以及为什么改）
- 具体改动点2
```

- **类型标签**：`feat`（新功能/规范）、`fix`（缺陷修复）、`docs`（文档更新）、`style`（格式调整）、`refactor`（重构）、`test`（测试）、`chore`（构建/配置变动）。

---

## 3. 分支管理与语义化版本 (SemVer)

- **分支命名**：`类型/简述`（如 `feat/user-auth`, `fix/null-pointer`, `refactor/interface-first`）；`main`/`master` 保持随时可发布。
- **SemVer 版本规则**：`主版本.次版本.修订号`（Major.Minor.Patch）。
  - **Major**：重大架构调整或破坏性变更。
  - **Minor**：新增向后兼容规则或特性。
  - **Patch**：修正错别字、润色描述、修补漏洞。
  - **改动必升版本**：任何涉及带版本号的文件修改，必须同步升级头部版本号并在 INDEX.md 记录变更摘要。

---

## 4. 仓库过滤与大文件存储 (LFS)

- **忽略规则 (.gitignore)**：严禁提交二进制编译产物、系统临时文件（`.DS_Store`）与 IDE 临时配置；UE5 项目必须过滤 `Binaries/`, `Intermediate/`, `Saved/`, `DerivedDataCache/`。
- **大文件存储 (Git LFS)**：多媒体资产、模型、纹理及 UE5 二进制文件（`.uasset`, `.umap`）必须在 `.gitattributes` 中配置 LFS，严禁直接检入普通 Git 存储库。
