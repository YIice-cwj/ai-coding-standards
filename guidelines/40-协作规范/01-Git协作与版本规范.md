# Git 协作与版本规范 (Git Collaboration & Versioning Standards)

**所属域**: 40-协作规范  **域版本**: 2.2.0  **日期**: 2026-10-26  **类型**: 全局通用协作规范（规则 SSOT）

> **SSOT 声明**：**"未获明确指令严禁擅自提交" (B-GIT)** 与 SemVer 版本升级契约的唯一权威源。
> **关联文档**：[核心铁律](../00-行为规范/01-核心铁律与五阶执行模型.md) · [规范总索引](../INDEX.md)。

---

## 1. 提交权限与执行铁律 (B-GIT SSOT)

| 规则 ID | 核心公理 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|:---:|---|---|---|
| **B-GIT** | **提交权限严格受控** | 仅在用户显式发出指令（如明确输入“提交”或“commit”）时方可执行提交与推送 | 未获用户明确指令，擅自执行 `git commit` 或 `git push` |

- **工作区暂存契约**：在未获提交指令前，AI 必须将修改保留在工作区，仅汇报改动摘要与验证依据，等待用户审查决定何时提交。

---

## 2. 提交信息结构化契约

提交信息必须采用标准化格式：
```
[类型]: 简短概述变更核心目的（<= 50 字）
- 具体改动点 1（改了什么 + 为什么改）
- 具体改动点 2
```
- **类型标签**：`feat`（新功能/规范）、`fix`（Bug 修复）、`docs`（文档/索引）、`style`（纯格式）、`refactor`（重构优化）、`test`（测试用例）、`chore`（工程构建/依赖）。

---

## 3. 分支管理与语义化版本 (SemVer)

- **分支命名**：`类型/简述`（如 `feat/user-auth`, `fix/null-pointer`, `refactor/narrow-tx`）；主干保持随时可发布。
- **SemVer 规则**：`主版本.次版本.修订号`（Major.Minor.Patch）。
  - **Major**：破坏性变更、核心架构重组。
  - **Minor**：新增向后兼容的规则、专著或特性。
  - **Patch**：错别字修正、局部表述润色、小缺陷修补。
  - **改动必升版本**：任何带版本号的规范修改，**必须同步提升文件头版本号并在 INDEX.md 登记变更**。

---

## 4. 仓库过滤与大文件存储 (LFS)
- **`.gitignore` 过滤**：严禁检入编译中间体、系统缓存（`.DS_Store`）与敏感凭据（`.env`）；UE5 必须过滤 `Binaries/`, `Intermediate/`, `Saved/`, `DerivedDataCache/`。
- **Git LFS**：多媒体资产、模型、纹理及 UE5 二进制文件（`.uasset`, `.umap`）必须配置 LFS，严禁直接检入普通 Git 仓库。
