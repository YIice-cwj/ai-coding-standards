## 1. 工程化与构建红线

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-WEB-PKG]** | MUST | 统一包管理器并提交 Lockfile；固定 Node 版本（`.nvmrc` 或 `engines`）；依赖升级需评审 | 混用 npm/pnpm/yarn；提交无 Lockfile 的浮动依赖；全局安装项目依赖 |
| **[R-WEB-ENV]** | MUST | 客户端仅注入非机密配置；机密仅存在于服务端环境或密钥管理；启动时校验配置 | 把密钥放入 `NEXT_PUBLIC_*`/`VITE_*` 等客户端变量；把 `.env` 提交到仓库 |
| **[R-WEB-BUILD]** | MUST | 生产构建启用压缩、Tree Shaking、Source Map 受控访问；设置 Bundle 预算并持续监控 | 关闭 Source Map 却无法定位线上错误；无预算的巨型首屏 Bundle；构建产物含调试代码 |
| **[R-WEB-DEP]** | MUST | 依赖锁版本并通过漏洞扫描；新增依赖评估许可证、维护性与体积 | 引入未审计依赖；忽略高危 CVE；为一个小功能引入巨型依赖 |

## 2. 测试策略

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-WEB-TEST-UNIT]** | MUST | 组件测试使用 Vitest/Jest + React Testing Library，按用户可见行为断言；核心组件覆盖分支与异常 | 只写快照测试；断言组件内部实现；全量 Mock 业务逻辑 |
| **[R-WEB-TEST-E2E]** | MUST | 关键用户旅程使用 Playwright/Cypress；测试数据隔离、可重复、可并行 | 用 `sleep` 盲等；依赖共享脏数据；用 E2E 替代单元测试 |
| **[R-WEB-TEST-COV]** | MUST | 核心业务组件与服务层遵循 [10/03](../10-通用代码规范/03-测试控制流与速查.md) 的 95% 行/分支覆盖率门禁 | 通过忽略注释/白名单虚抬覆盖率；只测正向路径 |

```tsx
// ✅ 正例：按用户可见行为断言，不依赖组件内部实现
it('submits the order and shows success feedback', async () => {
    render(<CheckoutPanel order={orderFixture} />);
    await userEvent.click(screen.getByRole('button', { name: '提交订单' }));
    expect(await screen.findByText('订单已提交')).toBeInTheDocument();
});
```

## 3. Web 安全基线

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-WEB-XSS]** | MUST | 默认转义输出；富文本使用可信 sanitizer；配置 CSP；禁止不可信 HTML 直接渲染 | 对不可信数据使用 `dangerouslySetInnerHTML`；拼接 HTML 字符串；用 `eval` 执行外部输入 |
| **[R-WEB-CSRF]** | MUST | 状态变更请求使用 CSRF Token 或 `SameSite` Cookie；写操作禁止 GET | 仅依赖 Cookie 的跨站写操作；GET 触发状态变更 |
| **[R-WEB-SECRET]** | MUST | 机密仅服务端可见；错误响应与日志不泄露密钥、Token 与内部堆栈 | 在客户端 Bundle、日志或错误提示中暴露机密 |
| **[R-WEB-SSRF]** | MUST | 服务端出站请求使用协议/域名 allowlist，阻断私网与云元数据地址 | 服务端直接抓取用户传入 URL |

```tsx
// ❌ 反例：不可信 HTML 直接渲染
<div dangerouslySetInnerHTML={{ __html: userComment }} />;

// ✅ 正例：富文本先经可信 sanitizer，纯文本默认转义
<div dangerouslySetInnerHTML={{ __html: sanitizeRichText(userComment) }} />;
```

## 4. 可访问性 (WCAG 2.1 AA 基线)

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-WEB-A11Y]** | MUST | 语义化 HTML、可访问名称、键盘可达、焦点可见、对比度达标、图片有替代文本 | `div` 当按钮；无 label；移除焦点轮廓；键盘陷阱；仅靠颜色传达状态 |

- 所有交互元素必须可通过键盘完成，并保持可见焦点。
- 表单控件必须有显式 label 或可访问名称；错误提示需与控件关联。
- 动态内容与弹窗必须管理焦点，并提供屏幕阅读器可感知的状态通知。

## 5. 性能与 Core Web Vitals

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-WEB-PERF]** | MUST | 以 LCP、INP、CLS 为验收指标，默认目标取 75 分位：LCP $\le 2.5\,s$、INP $\le 200\,ms$、CLS $\le 0.1$；优化前先测量；按路由/组件代码分割；图片使用合适格式与尺寸 | 凭感觉优化；仅凭 Lighthouse 分数验收；首屏加载全量 Bundle；未压缩大图；布局抖动 |
| **[R-WEB-CACHE]** | MUST | 静态资源使用内容哈希与长期缓存；API 缓存策略明确；避免重复请求 | 无缓存策略；频繁全量刷新；把敏感数据写入公共缓存 |
| **[R-WEB-OBS]** | MUST | 接入错误上报与性能监控；Source Map 受控上传；日志脱敏 | 无线上错误监控；上报 PII/Token；Source Map 公开暴露 |

### 5.1 度量与门禁

- **双轨口径**：Lighthouse CI 等 lab 数据用于 CI 断言与回归定位；`web-vitals` 采集的 field 数据用于真实用户验收；两者冲突时以 field 为准。
- **CI 断言**：使用 `@lhci/cli` 对关键路由执行 CWV 断言；默认目标即 §5 `R-WEB-PERF` 的 75 分位值，项目可经 ADR 调整。
- **包体预算**：可用 `size-limit` 或等价工具在 CI 断言首屏与路由级预算；超预算阻断（属 T1 预算型）。
- **微基准边界**：`vitest bench`/tinybench 仅用于纯函数热路径（如大列表计算、序列化、diff 算法）；禁止用微基准替代端到端 CWV 验收。
- **口径回链**：指标分层、环境稳定与门禁策略遵循 [10/03 §5](../10-通用代码规范/03-测试控制流与速查.md#5-性能验证与基准测试-performance-verification--benchmarking)。

## 6. 自检清单

- [ ] 包管理器唯一且 Lockfile 已提交；Node 版本已固定。
- [ ] 客户端环境中零机密；配置在启动时校验并快速失败。
- [ ] 生产构建有 Bundle 预算、Source Map 受控与依赖漏洞扫描。
- [ ] 核心组件具备行为断言测试；关键旅程有 E2E；覆盖率遵循 10/03。
- [ ] 不可信 HTML 全部经过 sanitizer；CSP 已配置；无 `eval`。
- [ ] 状态变更接口具备 CSRF 防护；无 GET 写操作。
- [ ] 服务端出站请求有 allowlist；敏感信息不进入日志或错误响应。
- [ ] 交互组件满足语义化、键盘可达、焦点可见与对比度要求。
- [ ] LCP/INP/CLS 已监控，首屏无巨型 Bundle 与明显布局抖动。
- [ ] 性能预算（Bundle 与 CWV）已声明并由 CI 断言，lab 与 field 数据均有采集。
- [ ] 错误上报与性能监控已接入，日志已脱敏。
