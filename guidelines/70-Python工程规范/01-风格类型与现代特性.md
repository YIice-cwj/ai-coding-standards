## 1. 语法约束与类型安全红线

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-PY-TYPE]**    | MUST | 公开函数与类方法必须标注形参和返回值类型；优先使用 Python 3.10+ 联合类型（`int | None`） | 顶层公共模块省略类型注解；使用动态黑盒对象 |
| **[R-PY-MUT-ARG]** | MUST | 可变类型默认值必须使用 `None` 占位，并在函数体内初始化 | **严禁使用可变对象（`[]`, `{}`）作为默认实参**（共享状态陷阱） |
| **[R-PY-SCHEMA]**  | MUST | 复杂外部输入数据与配置必须使用 `Pydantic v2` 或 `dataclass(slots=True)` 严格校验 | 使用无校验的裸 `dict` 在深层业务链路透传 |
| **[R-PY-EXC]**     | MUST | 精确捕获具体异常类型；严禁裸 `except:`；保留因果链 `raise ... from err` | 裸 `except:` 吞掉 `KeyboardInterrupt` 与语法错误 |
| **[R-PY-CTX]**     | MUST | 文件、网络 Session、锁等资源必须使用上下文管理器（`with` / `async with`） | 手动 `.open()` 且缺少 `finally` 释放保障 |
| **[R-PY-TOOL]**    | MUST | 以 `pyproject.toml` 为单一配置源；`ruff` 负责格式与 Lint，`mypy` 或 `pyright` 严格类型检查 | 多份散落的 `setup.cfg`/`tox.ini`/编辑器配置；用 `# type: ignore` 掩盖错误 |
| **[R-PY-CONFIG]**  | MUST | 环境配置使用 `pydantic-settings`，启动时校验并快速失败；机密来自环境或密钥管理 | 散落 `os.getenv`；默认值掩盖缺失配置；把机密写入代码或配置文件 |
| **[R-PY-LOG]**     | MUST | 使用结构化日志并绑定 `trace_id`；日志字段脱敏 | 裸 `print` 作为业务日志；日志明文输出 PII/Token |
| **[R-PY-SEC]**     | MUST | 外部输入在边界校验；禁止对不可信数据使用 `eval`/`exec`/`pickle`；密码使用强哈希 | 直接反序列化外部数据；拼接 SQL；硬编码密钥（详见 [10/08](../10-通用代码规范/08-应用安全规范.md)） |

## 2. 模式对比与正反例 (❌ vs ✅)

### 2.1 可变默认参数陷阱 [R-PY-MUT-ARG]
```python
# ❌ 反例：可变默认参数在函数调用间共享，产生幽灵数据
def add_item(item: str, bucket: list[str] = []) -> list[str]:
    bucket.append(item)
    return bucket

# ✅ 正例：使用 None 哨兵值并局部按需实例化
def add_item(item: str, bucket: list[str] | None = None) -> list[str]:
    target = [] if bucket is None else bucket
    target.append(item)
    return target
```

### 2.2 严格数据建模与类型校验 [R-PY-SCHEMA]
```python
# ❌ 反例：弱契约无校验裸字典
def process_order(payload: dict) -> None:
    order_id = payload["order_id"] # KeyError 隐患，且无类型推导

# ✅ 正例：Pydantic v2 强契约模型
from pydantic import BaseModel, Field

class OrderPayload(BaseModel):
    order_id: str = Field(min_length=1)
    amount: float = Field(gt=0)

def process_order(payload: OrderPayload) -> None:
    order_id = payload.order_id
```

### 2.3 统一工具链配置 [R-PY-TOOL]
```toml
[tool.ruff]
line-length = 100
target-version = "py310"

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP", "SIM", "RUF"]

[tool.mypy]
strict = true
warn_unused_ignores = true
```

### 2.4 类型安全的配置管理 [R-PY-CONFIG]
```python
from pydantic_settings import BaseSettings, SettingsConfigDict

class AppSettings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="APP_", extra="forbid")

    database_url: str
    request_timeout_s: float = 10.0
```

### 2.5 不可信输入的安全反序列化 [R-PY-SEC]
```python
# ❌ 反例：对不可信输入使用 eval
def load_payload(raw: str) -> dict:
    return eval(raw)

# ✅ 正例：强类型模型校验外部数据
def load_payload(raw: str) -> OrderPayload:
    return OrderPayload.model_validate_json(raw)
```

## 3. 自检清单 (Checklist)
- [ ] 源码通过 `ruff` / `mypy` 或 `pyright` 严格检查，公共契约具备完备类型注解。
- [ ] `pyproject.toml` 为单一配置源，无散落的 Lint/类型配置。
- [ ] 零可变默认实参（`def f(x=[])`）；零裸 `except:` 吞异常。
- [ ] 外部 I/O 资源 100% 纳入 `with` 上下文管理器托管。
- [ ] 配置通过 `pydantic-settings` 校验，机密来自环境或密钥管理。
- [ ] 日志结构化且脱敏，无 `print` 业务日志与 PII/Token 泄露。
- [ ] 不可信数据不进入 `eval`/`exec`/`pickle`，外部输入经强类型校验。
