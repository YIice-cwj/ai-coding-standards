## 1. 异步并发与环境工程红线

| 规则标识 | 约束级别 | 强制行为 (DO) | 严禁行为 (DON'T / 一票打回) |
|---|:---:|---|---|
| **[R-PY-ASYNC-BLOCK]**| MUST| 异步事件循环中遇到同步阻塞 I/O（`requests`, `time.sleep`, 传统文件读写），必须用 `asyncio.to_thread` 转入线程池 | 在 `async def` 函数中直接调用同步阻塞操作（阻塞整个事件循环） |
| **[R-PY-ASYNC-TASK]** | MUST| 派生并发任务必须持有 Task 强引用（`tasks.add(t)`），防止被 GC 提前销毁；优雅处理 `CancelledError` | 产生脱离监管的悬挂 Task；吞掉 `asyncio.CancelledError` |
| **[R-PY-ENV-LOCK]**   | MUST| 项目依赖必须通过 Poetry / uv / Pipenv 锁定版本，且**必须提交 Lockfile** | 裸用 `pip install`；`requirements.txt` 未锁定精确版本号 |
| **[R-PY-ASYNC-TIMEOUT]**| MUST| 所有外部调用必须设置超时（3.11+ 用 `asyncio.timeout`，3.10 用 `asyncio.wait_for`，或客户端超时）；超时后释放资源 | 无限等待网络/DNS/数据库；仅依赖默认超时 |
| **[R-PY-ASYNC-CANCEL]** | MUST| 取消信号必须向上传播；清理逻辑使用 `finally`/`asyncio.shield`；禁止吞掉 `CancelledError` | 捕获 `CancelledError` 后继续执行；取消时遗留半完成状态 |
| **[R-PY-BG-TASK]**    | MUST| 后台任务使用队列（Celery/ARQ/Dramatiq 等）并具备幂等键、重试上限、退避与死信处理 | 在请求链路内 fire-and-forget；无幂等重试；失败无告警 |
| **[R-PY-PYTEST]**     | MUST| 使用 `pytest` + `pytest-asyncio`；Fixture 隔离、可并行；异步测试用事件/虚拟时钟同步 | 共享可变 Fixture；测试依赖执行顺序；`time.sleep` 盲等 |
| **[R-PY-COV]**        | MUST| 核心业务执行 `pytest --cov=src --cov-branch --cov-fail-under=95`，覆盖异常与边界 | 只跑正向路径；用 `# pragma: no cover` 虚抬覆盖率 |
| **[R-PY-TEST-SLEEP]**  | MUST| 异步测试必须使用 `pytest-asyncio` 与事件同步；**严禁使用 `time.sleep` 盲等** | 测试用 sleep 盲等（违反真测试契约 B5）；全量 Mock 核心逻辑 |
| **[R-PY-BENCH]**       | MUST| 性能敏感路径使用 `pytest-benchmark`（或 `asv`/`pyperf`）建立基准；Release 等价配置、固定输入与种子、重复 $\ge 5$ 轮、输出 JSON 基线并做相对回归 | 基准混入常规测试套件；计入覆盖率；Debug/插桩下测；单次运行下结论 |

## 2. 模式对比与正反例 (❌ vs ✅)

### 2.1 异步非阻塞调用 [R-PY-ASYNC-BLOCK]
```python
# ❌ 反例：在异步协程内调用同步阻塞库，卡死主循环
async def fetch_remote() -> str:
    import time, requests
    time.sleep(1) # 严重违规！卡死所有并发协程
    return requests.get("https://api.internal/data").text

# ✅ 正例：使用异步 HTTP 客户端，或同步任务切入线程池
import asyncio
import httpx

async def fetch_remote() -> str:
    async with httpx.AsyncClient() as client:
        resp = await client.get("https://api.internal/data")
        return resp.text
```

### 2.2 真测试契约与异步断言 [R-PY-TEST-SLEEP]
```python
# ❌ 反例：假测试同义反复 + sleep 盲等
@pytest.mark.asyncio
async def test_order_timeout():
    await asyncio.sleep(2) # 盲等低效脆弱
    assert True

# ✅ 正例：时间模拟与精确状态断言
@pytest.mark.asyncio
async def test_order_timeout(event_bus, time_machine):
    time_machine.shift(delta_seconds=60)
    order = await get_order("order-123")
    assert order.status == OrderStatus.EXPIRED
```

### 2.3 外部调用超时与取消 [R-PY-ASYNC-TIMEOUT / R-PY-ASYNC-CANCEL]
```python
async def fetch_remote(url: str) -> str:
    async with httpx.AsyncClient() as client:
        response = await asyncio.wait_for(client.get(url), timeout=5)
        response.raise_for_status()
        return response.text
```

### 2.4 后台任务幂等与重试 [R-PY-BG-TASK]
```python
@task(bind=True, max_retries=3)
def send_receipt(self, order_id: str, idempotency_key: str) -> None:
    if receipt_store.exists(idempotency_key):
        return
    receipt_store.save(idempotency_key, render_receipt(order_id))
```

### 2.5 Fixture 隔离与覆盖率门禁 [R-PY-PYTEST / R-PY-COV]
```python
@pytest.fixture
def order_repo(db_session) -> Iterator[OrderRepository]:
    repo = OrderRepository(db_session)
    yield repo
    db_session.rollback()

@pytest.mark.asyncio
async def test_expire_order(order_repo, time_machine) -> None:
    time_machine.shift(delta_seconds=60)
    order = await order_repo.get("order-123")
    assert order.status == OrderStatus.EXPIRED
```

```bash
pytest --cov=src --cov-branch --cov-fail-under=95
```

### 2.6 基准测试与性能回归 [R-PY-BENCH]
```python
def test_serialize_orders(benchmark) -> None:
    orders = make_orders(count=1000)
    benchmark(serialize_orders, orders)
```

```bash
pytest --benchmark-only --benchmark-json=bench.json --benchmark-autosave
pytest --benchmark-only --benchmark-compare --benchmark-compare-fail=min:10%
```

- `--benchmark-compare-fail` 用于相对基线回归；阈值与复测策略遵循 [10/03 §5.4](../10-通用代码规范/03-测试控制流与速查.md#54-门禁策略)，默认中位数回退 10%。
- 长期趋势可用 `asv`；严谨微基准可用 `pyperf`；先 profile（`cProfile`/`py-spy`）再优化。
- 基准不计入 `--cov` 统计，也不进入常规单测套件。

## 3. 自检清单 (Checklist)
- [ ] 异步事件循环中零同步阻塞调用；阻塞 I/O 切入线程池，CPU 密集任务切入进程池。
- [ ] 所有外部调用具备超时，取消信号向上传播，无吞 `CancelledError`。
- [ ] 后台任务具备幂等键、重试上限、退避与死信处理，无请求内 fire-and-forget。
- [ ] 依赖管理工具锁死版本（`poetry.lock`/`uv.lock` 同步维护），绝不随意向全局注入三方包。
- [ ] 测试 Fixture 隔离、可并行、无执行顺序依赖，无 `sleep` 盲等用例。
- [ ] 核心业务覆盖率达到 95%（行/分支），异常与边界路径已覆盖。
- [ ] 性能敏感路径具备可复现基准与 JSON 基线，未混入常规测试套件或覆盖率统计。
